# 个人信用违约预测与评分卡模型

模拟银行个人信贷审批场景：基于历史客户的信贷记录与违约标签，预测客户未来两年内发生 90 天以上逾期的概率，并以评分卡的形式输出，供审批时参考。

- 数据：Kaggle *Give Me Some Credit* 公开数据集，150,000 条，10 个特征
- 主模型：逻辑回归（每分可解释），XGBoost 作效果上限参照
- 结果：测试集 AUC 0.8468 / KS 0.5367，评分分数与违约率严格单调

## 1. 数据介绍

数据来自 Kaggle 的 *Give Me Some Credit*（天池为转载），共 150,000 条个人信贷记录，特征包括循环贷使用率、年龄、月收入、负债率、三个逾期次数变量、公开信贷笔数、不动产贷款笔数、抚养人数等 10 个变量。

- 目标变量 `SeriousDlqin2yrs`：未来两年内是否出现 90 天以上逾期（1 = 违约，0 = 正常）
- 违约率 6.79%，类别不平衡，属于风控场景的常态

## 2. 数据预处理

拿到数据后先做了几轮排查，发现四类问题，分别处理：

**逻辑异常**：年龄 ≤ 0、循环贷使用率 > 13、负债率 > 50 的记录在现实中不可能出现，直接删除。

**编码脏值（96/98）**：三个逾期次数变量出现了 96、98 这样的取值——正常信贷记录逾期次数不会到近百次，而且这 260 条记录是三个字段同时异常，判断为同一批损坏数据，整批剔除。

**缺失值**：月收入、抚养人数存在缺失，用中位数填补（比均值更抗极端值）。

**极端值**：月收入存在 300 万的脏值，按 99 分位截尾（截尾值 25,000）。

处理前后样本量 150,000 → 123,584。

排查过程中有一个值得记录的发现：三个逾期次数变量在原始数据上两两相关系数高达 0.98，看起来严重共线、不能同时入模。进一步排查发现这是 96/98 脏值造成的假象——同一批损坏记录的三个字段被同时写成 98，极端杠杆点把相关系数人为抬高。剔除脏值后相关系数降到 0.2~0.3，三个变量刻画的是不同逾期阶段（30-59 天 / 60-89 天 / 90 天以上），可以同时入模。如果不做这一步排查，要么误删有效变量，要么带着脏值直接建模。

## 3. 特征工程

特征工程的核心是把原始变量转成 WOE 形式的入模变量。分箱边界在全集上确定，只用特征分布、不接触目标变量，避免目标泄漏，也保证训练/测试共用同一套边界。

**分箱方式**：连续变量先做等频初箱；逾期次数这类取值可枚举的变量按取值分箱（高频取值单独成箱、长尾合并）。分箱后计算每箱的 WOE 和 IV。

**单调性处理**：分箱后做相邻合并，把每个变量的 WOE 调到单调——比如循环贷使用率越高、违约风险越高，分箱后每个箱的 WOE 应随使用率单调上升。这样变量方向符合业务直觉，评分卡解释起来才说得通。

**变量筛选**：先用 IV > 0.02 筛掉区分能力弱的变量；再用相关性检查（两两 |corr| > 0.8 时保留 IV 更高者），因为逾期次数变量两两相关较高，全部入模会让逻辑回归系数不稳定。最终 8 个变量入模，最强信号是循环贷使用率（IV≈1.02）和 90 天以上逾期次数（IV≈0.80）。

筛选没有只看 IV 排名：IV 高不代表一定能留下，还要看变量间的相关性以及向业务解释的难易程度。各入模变量的 IV 见 `outputs/iv_bar.png`。

## 4. 模型构建

**模型选择**：主模型用逻辑回归，因为银行风控场景要求"分数扣在哪一项、为什么扣"都能向业务和合规解释。同时用 XGBoost 跑了一遍作效果上限参照——如果逻辑回归和 XGBoost 差距很大，说明可解释性的代价过高；实际 AUC 0.8468 vs 0.8555，差距不到 0.01，说明选逻辑回归是可接受的取舍。

**切分与验证**：按目标变量分层切分训练:测试 = 7:3（86,508 / 37,076）；训练集上做 5 折分层交叉验证，观察模型在不同数据划分下的表现是否稳定。

## 5. 评分卡转换

把逻辑回归的线性得分换算成评分卡形式：基准分 600、PDO=50（odds 每翻一倍扣 50 分），Factor = PDO / ln2 ≈ 72.13，基准 odds 用训练集整体违约率定义（0.0728，对应 600 分）。

每个变量的每个分箱对应一个加减分值（回归系数 × WOE，取整），输出 `outputs/scorecard.csv`，业务可以直接查表，例如：

- 循环贷使用率 ≤ 0.0447：+67 分；> 0.975：-69 分
- 90 天以上逾期 0 次：+14 分；≥ 2 次：-111 分

## 6. 模型评估

**测试集**：AUC 0.8468，KS 0.5367。
**5 折交叉验证**：AUC 0.8430 ± 0.0064，KS 0.5372 ± 0.0120，波动不大。
**XGBoost 参照**：AUC 0.8555。

数据没有申请时间字段，做不了严格的跨时间 OOT 验证，用 200 次 bootstrap 重采样估计测试集 AUC 的 95% 置信区间 [0.8385, 0.8555] 近似稳定性。

ROC 对比见 `outputs/roc_compare.png`，KS 曲线见 `outputs/ks_curve.png`。

## 7. 风险分层分析

**评分单调性**：测试集按分数十等分，违约率从最低分段 35.8% 单调降到最高分段 0.5%，分数越高风险越低（见 `outputs/score_monotonicity.png`）。

**评分分布**：正常客户与违约客户的分数明显分层，违约客户集中在低分段（见 `outputs/score_distribution.png`）。

**阈值-业务成本权衡**：不同分数阈值对应不同的拒绝率与被拒客群坏账率（见 `outputs/threshold_curve.png`）：

| 阈值 | 拒绝率 | 被拒客户坏账率 |
|---|---|---|
| 692.9 | 70.0% | 9.38% |
| 676.1 | 60.0% | 10.64% |
| 656.6 | 50.0% | 12.26% |
| 638.1 | 40.0% | 14.60% |
| 613.7 | 30.0% | 17.97% |
| 581.5 | 20.0% | 23.30% |

例如阈值取 613.7（拒绝率约 30%）时，被拒客户中实际违约的约占 18%，明显高于整体违约率 6.79%，说明这个阈值能有效拦下高风险客群；但阈值越严，被误拒的正常客户也越多，实际取值需要结合获客成本与坏账损失权衡，这里只给出分析框架。

## 10. 已知局限与后续方向

- 数据没有申请时间字段，无法做跨时间 OOT 验证与 PSI 群体稳定性监控，目前用 bootstrap 近似，后续可补充带时间维度的样本；
- 违约率 6.79% 属不平衡样本，后续可尝试好坏样本抽样后的先验概率校准；
- 尚未做特征衍生（如总逾期次数、使用率分档）和概率校准（预测 PD vs 实际违约率），是后续可以补的方向。
